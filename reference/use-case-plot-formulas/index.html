    Use case plot formulas#

    This page describes how the Use Cases page in the Streamlit visualizer turns simulation outputs into plot values. It mirrors the implementation in src/globi/tools/visualization/views/use_cases.py, results_data.py, utils.py, and plotting.py.

    Unless noted, aggregation over months for energy tables uses aggregate_by_measurement: sums all numeric columns that share the same (Measurement, Aggregation, Meter) after dropping the Month level.

    Shared energy metrics (retrofit and scenario comparison)#

    These definitions apply whenever a chart is built from EnergyAndPeak / Results.pq multi-index data (Measurement, Aggregation, Meter, Month).

    Per-building EUI (kWh/m²)#

    For each building row:

    \[ \text{EUI} = \sum_{\text{meters } m}\sum_{\text{months}} E_{m,\text{month}} \]

    where each \(E_{m,\text{month}}\) is taken from columns with Measurement = Energy, Aggregation = End Uses. This matches summing all End Uses energy cells for that building (annual total in kWh/m² after month aggregation).

    Per-building peak (kW/m²), map-only context#

    \[ \text{peak\_per\_sqm} = \max_{\text{raw peak cols}}\ \max_{\text{months}} P_{\cdot,\text{month}} \]

    using columns with Measurement = Peak, Aggregation = Raw.

    End use and fuel mix (stacked bars, percent)#

    After monthly aggregation, for each scenario the code computes, for every end-use or utility meter \(c\),

    \[ \text{raw}_{s,c} = \sum_{\text{rows } i} E_{i,c} \]

    where \(E_{i,c}\) is the aggregated annual value in cell (Energy, End Uses or Utilities, c, …) for row \(i\) (typically one row per building).

    Only positive \(\text{raw}_{s,c}\) are passed through. The D3 chart does not plot absolute energy: each horizontal bar is normalized to 100%. For scenario \(s\),

    \[ \text{display\_pct}_{s,c} = \frac{100 \cdot \text{raw}_{s,c}}{\sum_{c'} \text{raw}_{s,c'}} \]

    So segments show portfolio share of each end use or fuel under whatever physical units the parquet columns use; changes between scenarios reflect shifts in that mix.

    EUI distribution (KDE)#

    Input data per scenario: list of per-building EUI values (same definition as above).

    The D3 chart uses an Epanechnikov kernel density estimate on a uniform grid of 100 thresholds spanning the pooled min–max EUI across selected scenarios.

    • Bandwidth: \(h = \dfrac{x_{\max} - x_{\min}}{30}\) (or 1 if the range is degenerate), computed per scenario from that scenario’s EUI sample min/max.
    • Kernel (for standardized argument \(u = (t - v)/h\)):
      \(K(u) = \dfrac{0.75\,(1 - u^2)}{h}\) if \(|u| \le 1\), else \(0\).
    • KDE value at grid point \(t\):
      \(\hat{f}(t) = \dfrac{1}{n}\sum_{i=1}^{n} K_h(t - v_i)\)
      implemented as mean over values v of kernel(t - v) with kernel = epanechnikov(h).

    The filled area and line are scaled to a common vertical domain across scenarios.

    Retrofit analysis (with cost and emissions)#

    Uses extract_retrofit_comparison_data, which extends extract_comparison_data with cost and emissions when factors are supplied.

    Per-building energy cost and emissions#

    For each building, from annual Utilities consumption per fuel meter (kWh):

    \[ \text{energy\_cost} = \sum_{\text{fuel } f} kWh_f \cdot c_{f},\qquad \text{emissions} = \sum_{\text{fuel } f} kWh_f \cdot e_{f} \]

    where \(c_f\) and \(e_f\) are the user-entered $/kWh and kg CO₂/kWh for that fuel (after normalize_fuel_name matching).

    System (capital) cost#

    \[ \text{capital\_cost}_b = A_b \cdot \sigma_s \]

    for building \(b\) in scenario \(s\): \(A_b\) = conditioned floor area (m²), \(\sigma_s\) = system cost $/m² for that scenario. If area is missing, capital cost is 0.

    Total annual cost (bar chart)#

    \[ \text{total\_cost}_s = \sum_{\text{fuel } f} \left(\sum_{\text{buildings}} kWh_{f,b}\right) c_{f,s} + \sigma_s \sum_b A_b \]

    i.e. sum of scenario energy costs across fuels plus total capital cost for the scenario (system cost × total conditioned area).

    Total emissions (bar chart)#

    \[ \text{emissions\_total}_s = \sum_{\text{fuel } f} e_{f,s} \sum_{\text{buildings}} kWh_{f,b} \]

    Retrofit map metrics#

    The map dataframe adds:

    • \(\text{total\_energy}_b = \text{EUI}_b \cdot A_b\)
    • \(\text{total\_peak}_b = \text{peak\_per\_sqm}_b \cdot A_b\)
    • \(\text{total\_cost}_b = \text{energy\_cost}_b + \text{capital\_cost}_b\)

    Color scale is linear from min to max of the chosen column over displayed buildings.

    Scenario comparison#

    Uses only extract_comparison_data (no cost/emissions). Charts follow the same EUI KDE, end-use, and utilities stacked-bar formulas as in the retrofit section’s energy plots.

    Overheating analysis#

    Primary column plotted on the map, histograms, rankings, and EUI scatter is map_value, joined to building geometry from EnergyAndPeak / Results via building_id.

    BasicOverheating (exceedance hours)#

    Rows are filtered from the flat overheating table when:

    • Polarity == "Overheat"
    • Threshold [degC] == user-selected threshold
    • Aggregation Unit == "Building"
    • Group == user aggregation (Zone Weighted or Worst Zone)

    Then map_value = Total Hours [hr] from the simulation output for that building (one row per building after de-duplication). Unit: hours.

    ExceedanceDegreeHours (EDH)#

    Same filters as above. map_value = EDH [degC-hr]. Unit: °C·h (degree-hours). The simulator defines EDH; the UI plots the stored annual (or reporting-period) totals as given in the file.

    HeatIndexCategories#

    Filtered with Aggregation Unit == "Building" and Group mapped from UI Worst Zone → "Worst per Timestep", Zone Weighted → "Zone Weighted".

    • danger_hours metric:
      \(\text{map\_value} = \sum_{c \in \mathcal{D}} H_c\)
      where \(\mathcal{D}\) = {Extreme Danger [hr], Danger [hr], Extreme Caution [hr], Caution [hr]} and \(H_c\) is the column value for that category.
    • Single-category metrics: map_value = selected column (e.g. Normal [hr]).

    Portfolio KPIs (mean, median, P95, count)#

    For the current map_value series (all buildings with non-null numeric values):

    • \(\text{mean} = \frac{1}{n}\sum_i v_i\)
    • \(\text{median} = 50\text{th percentile}\)
    • \(\text{P95} = 95\text{th percentile}\) (pandas quantile(0.95))
    • \(n\) = count of values

    Threshold sensitivity (“fan”) chart#

    For BasicOverheating or ExceedanceDegreeHours only:

    • For each simulated temperature threshold \(T_k\), load map_value for every building (same aggregation as selected).
    • Bold line (portfolio mean): \(\mu_k = \frac{1}{n}\sum_i v_{i,k}\).
    • Faint lines: one polyline per building connecting \((T_k, v_{i,k})\).
    • For performance, at most 120 buildings are kept, preferentially those with high variance of the metric across thresholds.

    Worst-zone / zone-weighted ratio (scatter)#

    At the selected threshold and data source (hours or EDH):

    \[ r_i = \frac{M^{\text{worst\_zone}}_i}{M^{\text{zone\_weighted}}_i} \]
    • If the denominator is 0, the ratio is treated as NaN.
    • Ratios are clipped to \([0, 50]\) and non-finite values dropped.

    Axes: \(x = M^{\text{zone\_weighted}}_i\), \(y = r_i\), optionally colored by \(r_i\).

    Exceedance hours vs EDH (scatter)#

    When both outputs exist, for each building at the same threshold and aggregation:

    • \(x_i =\) BasicOverheating hours
    • \(y_i =\) ExceedanceDegreeHours EDH

    Inner join on building_id.

    Morphology vs EDH (trellis)#

    For each numeric column \(X\) from merged inputs/buildings.parquet (up to 6 columns, building overlap with simulated IDs):

    • Panel plots \((X_i, \text{EDH}_i)\) where \(\text{EDH}_i\) is map_value from EDH at the map threshold.

    Distribution histogram and area-weighted histogram#

    • Bins: \(B = 40\) equal-width bins from numpy.histogram on all non-null map_value (count chart).
    • Bin count for bin \(j\): number of buildings with \(v_i \in [e_j, e_{j+1})\).
    • Conditioned floor area per bin:
      \(\text{area}_j = \sum_{i:\, v_i \in \text{bin } j} A_i\)
      using numpy.histogram with weights = conditioned_area (same edges). If conditioned_area is missing from the merge, only the count chart is shown.

    Metric vs temperature threshold (line charts)#

    For each threshold \(T\) in the run (from output files):

    • \(\text{mean}(T) = \frac{1}{n}\sum_i v_i(T)\) — mean of building-level metric at \(T\) (same aggregation).
    • \(\text{frac\_nonzero}(T) = \frac{1}{n}\sum_i \mathbf{1}[v_i(T) > 0]\) — fraction of buildings with strictly positive metric.

    median is computed in code for the summary dataframe but the two line charts in the UI plot mean and frac_nonzero only.

    Building map coloring#

    Buildings are filtered by a user metric range slider (map_value between \(v_{\min}, v_{\max}\)). Colors use a red colormap linearly from min to max of map_value on the filtered set.

    Rankings table#

    Rows sorted by map_value descending; columns include building_id, map_value, and eui if present.

    Overheating vs EUI scatter#

    Points \((v_i, \text{EUI}_i)\) where \(v_i\) is map_value and \(\text{EUI}_i\) comes from the same map table (kWh/m²). Axes labels reflect the overheating metric (hours, degree-hours, or heat-index label).

    What this document does not define#

    Simulation engines compute raw overheating hours, EDH integrals, and heat-index category hours. This doc only records filters, joins, aggregations, and display transforms applied in the visualizer. For physical definitions of EDH and heat index, refer to your simulation tool documentation and manifest configuration.
